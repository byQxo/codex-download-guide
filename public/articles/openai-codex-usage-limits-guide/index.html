OpenAI Codex 用量限制：Plus、Pro 5x/20x、Business Credits 和 API Key 怎么看

OpenAI Codex 的用量限制不是一个每日 token 数字。先分清你在看 ChatGPT 计划窗口、Business / Enterprise credits，还是 API key 计费，再看当前数字。

先给可以直接用的答案：OpenAI Codex 现在没有一个适用于所有人的统一“每日 token 上限”。截至 2026 年 4 月 21 日，真正生效的限制取决于你用的是 ChatGPT 计划包含用量、Business / Enterprise credits，还是 API key 按量计费。

这件事容易被问错，因为 OpenAI 现在用不同单位描述 Codex。Plus 和 Business 是按模型与活动拆开的 5 小时窗口；Pro 分成 Pro 5x 和 Pro 20x，并且有持续到 2026 年 5 月 31 日的临时提升；API key 则是按 API pricing 与 API rate limits 走，不是订阅计划额度。

所以不要先找别人截图里的“每天多少”。先打开 Codex usage dashboard，CLI 会话里看 /status，确认自己在哪条分支，再决定该看哪个数字。

证据说明： OpenAI Codex pricing、Codex authentication 和 API rate-limit 文档已在 2026 年 4 月 21 日重新核对。

这些数字要按“当前合同快照”读，不要当成你每次会话都能拿到上限。OpenAI 明确说实际可用量会受 model、task size、complexity、local/cloud 执行方式影响。短小本地任务和长时间云端任务，不能当成同一个消耗单位。

为什么你感觉到的限制会不一样

同一个 plan 下，不同人的体验也可能不同。主要变量有：

  • 模型选择： GPT-5.4-mini 能让 routine local tasks 更耐用。
  • 上下文与任务大小： 大仓库、长会话、复杂任务会更快消耗窗口。
  • local / cloud： local messages 和 cloud tasks 共用 5 小时窗口，但消耗体感不同。
  • speed 与 image generation： fast 配置会更快消耗 credits；Codex image generation 也会更快用掉包含限制。
  • 提示与工具开销： 过大的 AGENTS.md、不必要的 MCP servers 都会增加上下文成本。

更好的问题不是“每天多少 token”，而是“我当前是哪种任务在消耗哪条合同，能不能换模型、缩短上下文，或切换计费路线”。

Business、Enterprise 与 token-based credits

Credits 是超出包含用量后的续用单位。Plus / Pro 可以买 additional credits；Business、Edu、Enterprise 如果走 flexible pricing，可以买 workspace credits。

团队合同现在还多了一层变化：OpenAI 当前 pricing 页面说明，自 2026 年 4 月 2 日起，新老 Business 客户和新的 Enterprise 客户正在迁往 API token-based rates。新表按每 100 万 input tokens、cached input tokens、output tokens 消耗 credits。

但这不等于所有 Codex 用户都已经 token-metered。OpenAI 同时说明，其他 plan type 在迁移前仍使用旧的 message-based rate card。Enterprise / Edu flexible pricing 可以随 credits 扩展；没有 flexible pricing 的 Enterprise / Edu 多数功能接近 Plus per-seat limits。

所以不要把团队页读成“Business 全部无限”，也不要把 token credits 套到 Plus / Pro 上。先确认 workspace 和 seat 类型。

API key 分支是什么

API key 适合额外本地任务、CI 自动化、或你想用更明确的 usage-based economics 管理成本。但它不是 ChatGPT plan 限制的同一张表。

OpenAI 当前 Codex pricing 写明，API Key 可用于 CLI、SDK、IDE extension；不包含 GitHub code review、Slack integration 等 cloud features；新模型如 GPT-5.3-Codex / Spark 在 API key 路线也可能更晚可用。

API rate limits 本身按 RPM、RPD、TPM、TPD、IPM 等维度计算，并且可以在组织或项目层面生效，还会受模型与 monthly spend limits 影响。API 的问题不是“每日 token cap”，而是吞吐、计费和账户限制管理。

如果你继续研究 API 入门成本，应该单独看 OpenAI Platform 的 API key、定价和 rate limits 文档，而不是把它和 ChatGPT 计划窗口混在一起。

撞到限制后怎么做

  1. 先看官方面板。 用 Codex usage dashboard；CLI 中用 /status。
  2. 把 routine work 切到 GPT-5.4-mini。 OpenAI 说 mini 通常能让 local-message limits 延长约 2.5x 到 3.3x。
  3. 减少上下文开销。 精简 prompt、拆小 AGENTS.md、关掉不需要的 MCP servers。
  4. 临时超量用 credits。 Plus / Pro 买 additional credits；flexible workspace 买 workspace credits。
  5. 额外本地任务走 API key。 当工作更适合按量计费时，API key 比继续追订阅 headroom 更清楚。

FAQ

OpenAI Codex 有每日 token 上限吗？

没有一个通用的每日 token 上限。当前限制要按 plan windows、credits 或 API rate limits 分开看。

Plus / Pro 是 daily limit 吗？

不是。当前官方表主要是 5 小时窗口；Pro 还分 Pro 5x 和 Pro 20x。

Business 和 Plus 一样吗？

当前 included-usage 表里 Business 与 Plus 的数字相同，但 Business 还可能涉及 standard seats、usage-based seats、flexible pricing 和 workspace credits。

API key 和 ChatGPT plan 限制一样吗？

不一样。API key 是 usage-based，只适合本地 CLI / SDK / IDE extension 等路线，不包含 Codex cloud features。

在哪里看剩余用量？

看 Codex usage dashboard；CLI 活跃会话里用 /status。

结论

Codex 用量限制不是一个数字问题，而是先识别合同：计划窗口、workspace credits，还是 API key。
